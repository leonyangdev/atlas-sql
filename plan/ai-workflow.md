# 与 AI 协作开发

## 一次任务的输入

复制下面模板，并替换任务编号：

```text
请阅读 AGENT.md、原始项目总纲、plan/README.md 和当前阶段计划。
本次仅实现 V0-S01-T01（替换为真实任务 ID）。
先检查前置任务与现有代码，说明业务目的、输入输出、影响模块和验收方式。
实现时追求简洁可读；不要提前引入未来阶段能力，不要编造已存在的接口。
完成相关检查后，更新 plan/evidence 的证据和 altassql-book 对应学习章节。
解释一个关键调用链、一个失败场景、一个设计取舍。
只有验收通过才勾选任务；未通过保留未完成，并报告阻塞与下一步。
```

## 学习者每次要做的事

1. 不看代码，先根据故事写出你认为的输入、输出和失败条件。
2. 看 AI 的测试：它是否证明业务行为，而非仅调用实现？
3. 按 API → 编排 → 业务模块 → adapter 的顺序读代码，在纸上画出调用关系。
4. 修改一个条件，例如把区域改为无权限区域，先预测结果再运行。
5. 用两分钟解释：问题、方案、取舍、证据、尚未解决什么。

## 结束报告格式

```text
任务：Vx-Sxx-Txx
业务行为：
真实代码入口：
调用关系：
验证命令与结果：
关键失败案例：
设计取舍：
学习站更新：
证据文件：
任务是否可勾选及理由：
```

不要接受“应该能跑”“准确率预计提升”“企业级最佳实践”等替代实测。示例数据、fake 模型和真实 Provider 的测试要分别注明。模型生成的 SQL、元数据注释、用户反馈都不能作为可信系统指令。
