# V0-S02 验收记录

- 日期 / 执行者：2026-09-08 / Codex 与项目作者
- 已验收任务：V0-S02-T01～T04
- 真实入口：`datasets/schema/catalog.py`、`datasets/migrations.py`、`semantic_models/drafts/core_metrics.yaml`

## 逐项证据

### V0-S02-T01

- `uv run python scripts/build_schema_catalog.py` 生成 `datasets/dictionary/catalog.json` 和 `datasets/dictionary/domain-relationship.md`。
- 生成结果为 7 个业务域、56 张表、816 个字段；每个域 8 张表，满足 50～80 表和 600～1000 字段约束。

### V0-S02-T02

- 每张表声明类型、粒度、权威来源、时间含义、历史策略和状态枚举。
- 每个字段声明类型、可空性、敏感等级；主键、外键与关系基数可以机器读取。
- 目录覆盖事实表、维表、桥表、历史表、快照表和聚合表，并包含 SCD2、双时态及版本化快照。
- `tests/test_schema_catalog.py` 校验规模、域、唯一主键、引用目标、基数、枚举和建模挑战覆盖。

### V0-S02-T03

- 10 个指标草案记录表达式、粒度、过滤条件、时间归属、零分母与待决冲突。
- 默认使用 Asia/Shanghai、左闭右开时间区间和含税口径；支付与退款分别按事件时间归属。
- `tests/test_metric_drafts.py` 验证核心指标、时间规则、零分母和冲突没有被静默隐藏。
- 模拟 NovaRetail Analytics Council 仅批准这些定义用于 V0 测试数据；生产发布仍需 V3 治理流程。

### V0-S02-T04

- `scripts/build_business_migration.py` 从同一业务目录生成 `001_nova_retail_schema.sql`；CI 检查生成物没有漂移。
- `scripts/migrate_business.py` 首次运行返回 `001: applied`，第二次返回 `001: skipped`；迁移表记录 SHA-256，禁止修改已执行版本。
- PostgreSQL 实测 public schema 为 56 张表，外键和外键索引在全部表建立后统一添加。
- 迁移后使用 `atlas_reader` 查询 20 万订单成功；INSERT 返回 `cannot execute INSERT in a read-only transaction`。
- `datasets/fixtures/access_scopes.yaml` 提供北区、南区、单店和空权限四类身份，供 V4 接入真实授权策略时复用。

## 结论与限制

- 结论：V0-S02-T01～T04 全部通过，故事完成。
- 限制：区域和门店身份当前是测试夹具；可信身份注入和查询级行权限在 V4 实现。
- 学习站：`altassql-book/stages/v0.md`、`altassql-book/architecture/code-map.md`。
