## 逐项证据

### V1-S02-T01 模型网关与 Provider

`LLMGateway` 只暴露模型版本、非敏感参数和 `complete`。DeepSeek 实现调用
`POST /chat/completions`，启用 `response_format={"type":"json_object"}`，关闭 thinking，限制
max_tokens，并读取 prompt/completion/total token。HTTP 429、5xx、4xx、传输超时和无效响应
分别映射到稳定异常，错误中不包含 API Key 或响应正文。

Fake 对相同 Prompt 返回完全相同的 JSON、请求 ID 和 token 计数，并可注入延迟或错误。
项目将 `httpx[socks]` 作为运行依赖，真实调用可使用当前开发机的 SOCKS 代理。

DeepSeek 官方依据：

- `https://api-docs.deepseek.com/`：OpenAI-compatible base URL、模型和认证方式。
- `https://api-docs.deepseek.com/guides/json_mode/`：JSON Output 参数、Prompt 要包含 JSON 格式说明、
  合理设置 max_tokens，以及空 content 的已知情况。

### V1-S02-T02 版本化 Prompt 与调用记录

- Prompt 版本为 `v1-sql-generation-001`，方言固定 PostgreSQL。
- Schema 只从 V1-S01 的 15 表白名单渲染，机密字段不进入 Prompt。
- 只加入范围阶段识别出的指标草案；示例为仓库内 train 用例，不读取 tune/test。
- Prompt hash 对 Prompt 全文和模型参数做 SHA-256；问题、版本或模型参数变化都会改变 hash。
- `query_record` 保存 prompt_version/hash、模型参数、Provider 请求 ID 及三类 token 数；不保存
  API Key，也不把完整 Prompt 写入日志。

### V1-S02-T03 结构化解析和失败分类

本地 Pydantic 校验要求 action/sql/reason 三个字段且禁止多余字段。模型完整输出上限 20,000
字符，SQL 上限 10,000 字符；`generate` 必须有非空 SQL，澄清/拒绝不得夹带 SQL。

整个调用（含重试）受 QueryContext 的 timeout_ms 总预算限制；默认最多重试一次。已覆盖：

- 无 SQL → `llm_no_sql`
- 非 JSON、字段错误、过长输出 → `llm_invalid_output`
- 限流重试耗尽 → `llm_rate_limited`
- 总预算耗尽 → `llm_timeout`
- Provider 4xx/5xx → `llm_provider_error`

## 设计取舍与限制

- 默认 Provider 是 Fake，避免开发启动或测试时意外产生外部费用；显式设置
  `ATLAS_LLM_PROVIDER=deepseek` 才调用真实模型。
- DeepSeek JSON Output 保证 JSON 语法，不保证业务 Schema；本地必须二次强校验。
- Prompt 只存 hash，不持久化全文，兼顾复现指纹与问题数据最小化；完整模板由版本化代码重建。
- S02 不执行候选 SQL。AST 白名单、只读事务和结果上限属于 V1-S03。
