## 逐项证据

### V1-S04-T01 七种用户可见状态

前端 `DataAnalystHome` 组件覆盖全部可见状态：

| 状态 | 触发条件 | 前端展示 |
|------|---------|---------|
| 提问 | 文本框输入 + 提交 | 问题输入框（maxLength=2000，字符计数）|
| 处理中 | `status === "processing"` 轮询 | `正在生成并安全校验 SQL…`（aria-live）|
| 成功表格 | `status === "succeeded"` | 摘要 + 执行时间 + 表格 + SQL 详情折叠 |
| 空结果 | `rows.length === 0` | `没有符合当前条件的记录。这不等同于指标数值为零。` |
| 澄清 | `status === "clarification_required"` | `需要补充信息` + error.message + trace_id |
| 拒绝 | `status === "rejected"` | `当前范围暂不支持` + error.message + trace_id |
| 失败 | `status === "failed"` | `查询没有完成` + 保留问题并重试按钮 + trace_id |

重试按钮（失败/网络错误）：`onClick={() => void submit()}`，保留 `question` 状态不清空，
防止用户重新输入。`requestSequence` 计数器阻止旧请求的响应覆盖新请求结果。

SQL 与数据来源以 `<details>`/`<summary>` 包装，默认折叠，不直接注入页面顶层。

### V1-S04-T02 列类型映射、金额精度与时区

`formatCell(value, type)` 函数处理所有展示转换：

- **日期**：`type.includes("date") && !includes("timestamp")` → `String(value)`（保留原始格式）
- **时间戳**：`new Intl.DateTimeFormat("zh-CN", { timeZone: "Asia/Shanghai" })` 精确到秒
- **金额 / Decimal**：后端 `_serialize_cell` 在 `server/execution/postgres.py` 以 `format(value, "f")` 字符串返回；前端直接 `String(value)`，**不转 JS Number**，避免 `Number("1234567890.99")` 的浮点精度损失
- **NULL**：显式展示 `"NULL"`，有 `.null` CSS 类供样式区分
- **Boolean**：`"是"` / `"否"`
- **截断提示**：`truncated === true` 时显示 `结果已达到返回上限，仅显示前 N 行`

表头同时展示列名和 `data_type`（`<small>` 标签），方便用户核对类型。

### V1-S04-T03 仅依据返回结果的摘要，XSS 防护，防重复提交

**摘要生成**（`server/generation/answer.py`，`ResultSummaryBuilder.build`）：

- 只读取 `columns`、`rows`、`truncated`，不调用模型，不注入业务上下文。
- 空结果返回 `"没有符合条件的记录"`，不生成"数值为零"等错误断言。
- 单值数值结果（1×1 表格）：`"{列名}为 {值}"`。
- 单行多列：`"{col1} {v1}，{col2} {v2}，…"`（最多 5 列）。
- 多行：`"共 {N} 行结果"` 或截断后 `"显示前 {N} 行"` — 不捏造统计数字。

**XSS 防护**：

- React 默认对所有文本节点转义，`question`、`summary`、`error.message` 均通过 JSX 渲染，
  不使用 `dangerouslySetInnerHTML`。
- SQL 通过 `<pre><code>{result.sql}</code></pre>` 渲染，不作 HTML 插入。
- 表格单元格通过 `formatCell` 返回字符串，经 React 转义后渲染。

**防重复提交**：

```typescript
const requestSequence = useRef(0);
const sequence = ++requestSequence.current;
// 只有 sequence === requestSequence.current 时才更新状态
```

提交期间按钮 `disabled={submitting}`，旧异步回调若与新序列号不符则被静默丢弃。

**请求失败**（网络层）：独立 `networkError` 状态，不覆盖已展示的成功结果；
`"保留问题并重试"` 按钮调用 `void submit()`，问题输入不清空。

## 设计取舍与限制

- 轮询最多 30 次（30 秒），足够覆盖 V1 的同步执行；V2 引入流式时可移除轮询。
- 摘要生成无模型调用，避免因摘要产生幻觉，保证与表格数值一致性。
- `formatCell` 不覆盖所有数据库类型；遇到 `bytea`、自定义类型等退化到 `String(value)`，
  后端 `_serialize_cell` 也以 `str(value)` 兜底，不抛异常。
- 空结果的措辞"这不等同于指标数值为零"是刻意设计，避免用户将空查询结果误解为业务指标归零。
