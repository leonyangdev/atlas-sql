## 真实入口与关键调用关系

```text
POST /api/v1/query
  → QueryRequest 校验
  → QueryOrchestrator.submit
  → assess_sales_scope
  → QueryPipeline（V1-S02 接入；当前未配置时保持 processing）
  → QueryRepository
  → query_record（控制库）
```

关键文件：

- `server/domain/query.py`：QueryRequest / QueryResponse / QueryTrace、状态和错误码。
- `server/domain/sales_scope.py`：15 张表的显式字段白名单、指标别名、跨域拒绝规则。
- `server/orchestrator/query.py`：显式编排，传递身份、版本和超时预算，统一清洗内部异常。
- `server/query/models.py`、`repository.py`：控制库模型、仓储端口、SQLAlchemy 与内存实现。
- `server/api/query.py`：提交和按 trace_id 查询状态的 HTTP 入口。
- `migrations/versions/9cb21c73e4a1_v1_s01_问数请求基线.py`：请求记录表迁移。

## 逐项证据

### V1-S01-T01 问数契约

契约覆盖 question、session_id、trace_id、status、SQL、列、行、错误码、截断标记及 QueryTrace。
问题会先去除首尾空白；空白问题与超过 2,000 字符的问题由 Pydantic 拒绝。

测试：`tests/test_query.py::test_query_request_*` 与两个 API 验收测试。

### V1-S01-T02 固定 Sales 范围

- 固定 15 张表，包含 8 张 Sales 表和 7 张高频关联维表。
- 字段逐项显式列出；目录新增字段不会自动进入白名单。
- `tenant_id`、`source_record_id`、订单号和支付/退款单号等机密字段未开放。
- “销售额”等词映射到 V0 已审查草案 ID；“收入/营收”要求确认销售净额或财务入账收入。
- 库存、仓库、财务、成本、营销等明确跨域词在进入生成链路前拒绝。

测试验证白名单恰好 15 张表、所有表字段真实存在、机密和未知字段被拒绝。

### V1-S01-T03 显式编排与持久化

`QueryOrchestrator` 不依赖任何模型 SDK。`QueryPipeline` 接收不可变 `QueryContext`，其中包含
identity、data/schema/model version、trace_id、metric_ids 和 timeout_ms。每次请求先写入
`processing`，随后更新为成功、澄清、拒绝或失败；未知异常仅返回 `internal_error` 和通用提示。

真实控制库验证：

```text
uv run alembic upgrade head
→ upgrade 6bdae843a9d5 -> 9cb21c73e4a1

销售问题 → HTTP 202 / processing / metric_ids=[net_sales]
库存问题 → HTTP 200 / rejected / error.code=out_of_scope
```

## 设计取舍与限制

- S01 不伪造 SQL 或结果。尚未接入 S02 的模型网关时，合法销售请求保持 `processing`。
- 当前 `x-atlas-identity` 只是 V1 的可信上游占位；V4 必须由认证中间件提供身份。
- 范围识别是保守边界规则，不承担 V2 的域分类或跨域召回。
- 真实 SQL 生成、AST 安全和只读执行分别属于 V1-S02、S03，当前尚未实现。
