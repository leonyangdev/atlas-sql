```text

```

## 逐项证据

### V0-S04-T01 数据源登记 + 连接测试 + 权限检查

- `DataSource` 模型含 slug（唯一）、credential_ref（只允许 `env:` / `vault:` 前缀）、status。
- `POST /api/v1/datasources` 创建；`POST /api/v1/datasources/{slug}/test-connection` 测试。
- 响应体不回显 credential_ref 解析后的明文连接串；`check_min_privileges` 对高权限账户发警告。
- 错误场景：slug 重复返回 409；credential_ref 格式非法返回 422；token 错误返回 403。

测试入口：`tests/test_datasource.py` 26 个测试，全部通过（不依赖真实数据库）。

### V0-S04-T02 元数据采集

- `inspector.collect_tables` 通过 `information_schema.tables / columns` + `pg_catalog` 采集：
  表名、类型、行估算、注释、所有列的类型/可空/默认值/主键/外键、经过敏感过滤的样例值。
- 样例值跳过含 `password / token / hash / mobile / email / credit_card / secret` 的列名。
- `server/datasource/sync.py:_upsert_metadata` 写入 `table_metadata` 和 `column_metadata`。

验收命令：
```bash
uv run alembic upgrade head
# 部署后注册数据源并触发同步
curl -X POST http://127.0.0.1:8000/api/v1/datasources/nova-retail/sync \
  -H "x-admin-token: $ATLAS_ADMIN_TOKEN"
```

### V0-S04-T03 人工注释保留

- `TableMetadata.manual_*` 和 `ColumnMetadata.manual_*` 字段在 `_upsert_metadata` 中故意不覆盖。
- `PATCH /api/v1/metadata/tables/{id}` 只允许更新 `manual_*` 字段（`exclude_unset=True`）。
- 测试 `test_sync_preserves_manual_fields`：mock session 验证 `manual_business_name` 同步后保持不变。

### V0-S04-T04 Celery + Redis 同步任务

- `MetadataSyncJob` 模型含 `idempotency_key`（唯一索引）、`retry_count`、`status`、`error_summary`。
- `sync_datasource_task` 每次失败后递增 `retry_count`，达到 `MAX_RETRIES=3` 后不再 retry。
- `POST /api/v1/datasources/{slug}/sync` 优先派发 Celery；Celery 未配置时同步执行（开发/测试友好）。
- 连接失败信息只以 `type(exc).__name__` 写入 `error_summary`，不泄露 host/密码。
