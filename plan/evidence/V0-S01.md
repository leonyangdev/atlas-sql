## 逐项证据

### V0-S01-T01

- 后端骨架：FastAPI、Pydantic Settings、SQLAlchemy async、Alembic，依赖由 `pyproject.toml` 和 `uv.lock` 锁定。
- 前端骨架：`apps/web` 与 `apps/admin` 两个 Next.js 应用，依赖由根 `package-lock.json` 锁定。
- `uv run alembic upgrade head --sql` 成功；迁移目录暂为空，首个控制库实体在 V0-S04 引入。

### V0-S01-T02

- `docker compose --env-file .env.atlas up -d` 成功启动两个 PostgreSQL、Redis、OpenSearch、Milvus、etcd 和 MinIO。
- `docker compose ... ps` 显示 7 个服务全部为 `healthy`。
- 命名卷、服务健康检查、重启策略与 `.env.example` 已提交；业务库使用独立端口、数据库和只读账户。

### V0-S01-T03

- 正常态：`GET /health/live` 返回 200；`GET /health/ready` 返回 200，并报告五项依赖为 `up`。
- 故障态：停止 OpenSearch 后，liveness 仍返回 200，readiness 返回 503，错误仅为 `dependency_error`，没有暴露连接串或异常详情。
- 恢复态：启动 OpenSearch并进入 healthy 后，readiness 恢复为 200。
- `tests/test_config.py` 覆盖缺失配置、非法 URL、控制库与业务库误用同一数据库、配置脱敏。

### V0-S01-T04

- CI 执行 Ruff format/lint、Mypy、pytest 与 85% 服务端覆盖率门槛，以及两个 Next.js 应用的 typecheck/build 和 Compose 配置校验。
- 保留命名卷的全服务启动实测 22 秒；刚进入 healthy 时容器总内存约 1.38 GiB。
- 详细单服务快照与降载方式见 `docs/development/v0-s01-resource-baseline.md`。
