## 逐项证据

### V0-S05-T01 稳定文档 ID + OpenSearch mapping + Milvus schema

文档 ID 规则：
- 表：`table:{datasource_id}:{schema}.{table}` — 相同对象多次索引 ID 不变
- 列：`column:{datasource_id}:{schema}.{table}.{column}`
- 指标：`metric:{metric_id}`
- 验证查询：`verified_query:{id}`
- 超过 255 字节时降级为 `{前40字符}#{sha256前16字符}`

OpenSearch mapping 关键设计：
- `dynamic: strict` 防止 field type 爆炸
- 中文使用 `ik_max_word`，列名/代码使用 `word_delimiter_graph`
- `authorized_roles` 字段为 keyword 数组，V4 检索时过滤权限

Milvus schema 关键设计：
- `doc_id` varchar 主键与 OpenSearch `_id` 一致
- BGE-M3 维度 1024，`HNSW + IP` 度量（适合归一化向量）
- `metadata_version` 字段检测 stale 向量；维度变更需新建 collection

### V0-S05-T02 EmbeddingProvider 抽象

`EmbeddingProvider` 是 Protocol，实现类不需要显式继承。  
`FakeEmbeddingProvider` 用文本哈希生成确定性假向量（不依赖 GPU/网络，CI 可用）。  
`BGEM3EmbeddingProvider` 封装 FlagEmbedding，未安装时开发环境自动降级 Fake。

索引构建流程（`server/tasks/index_build.py`）：
1. 从控制库读取 `TableMetadata + ColumnMetadata`（is_deleted=False）
2. 调用 `EmbeddingProvider.embed_batch` 批量生成向量
3. OpenSearch bulk upsert（过滤 `_vector` 字段）
4. Milvus REST upsert
5. 核对 OpenSearch 和 Milvus 文档数量 == expected
6. 全部通过后 `PublishedIndexVersion` upsert

### V0-S05-T03 控制库同步状态 + 索引重建命令

`IndexBatch` 模型跟踪每次构建的状态（PENDING → BUILDING → PUBLISHED / FAILED）。  
`PublishedIndexVersion` 只保留最新已发布批次的指针；检索层读此表确定使用哪个 collection。  
维度变更后的流程：删除旧 Milvus collection → `rebuild_index.py` 新建 collection → 核对后切换指针。

```bash
# 同步执行索引重建（开发/调试）
uv run python scripts/rebuild_index.py --index-type schema

# 通过 Celery 异步执行
uv run python scripts/rebuild_index.py --index-type schema --via-celery
```

### V0-S05-T04 Redis key 命名空间 + TTL + smoke 检查

命名规则：`atlas:{env}:{datasource_id}:{version}:{category}:{key}`

TTL 分级：
- Schema 缓存：86400s（24h）
- 指标缓存：43200s（12h）
- 查询结果：300s（5min）
- Session 上下文：7200s（2h）
- 速率限制：60s
- 分布式锁：30s

失效触发：元数据同步成功后通过 `SchemaCache.invalidate_datasource` SCAN 批量删除该数据源的全部 schema 缓存（避免 KEYS 全扫描）。

四类基础设施 smoke 检查由 `DependencyChecker`（已在 V0-S01 实现）覆盖：控制库/业务库/Redis/OpenSearch/Milvus。

测试入口：`tests/test_search_infra.py` 31 个测试全部通过（不依赖真实基础设施）。
