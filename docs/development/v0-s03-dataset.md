# V0-S03 确定性数据说明

## 三档配置

| 配置 | 订单 | 每单明细 | 订单明细 | 用途 |
| --- | ---: | ---: | ---: | --- |
| tiny | 24 | 3 | 72 | 单元学习与快速手算 |
| dev | 20,000 | 5 | 100,000 | 日常功能与查询开发 |
| scale | 200,000 | 5 | 1,000,000 | V0 规模验收 |

三档配置使用相同 seed `20260908`、业务时钟 `2026-06-30T16:00:00Z` 和 schema version `001`。每次运行先清空 56 张业务表，在单个事务内写入并验证，失败时不会留下半成品快照。

## 数据边界

- 订单时间覆盖 2024-06 至 2026-06，支付和退款使用各自的事件时间。
- 订单、明细、支付和退款金额可对账；库存满足“可用量 = 在手量 - 预占量”。
- 包含匿名订单、测试订单、取消订单、缺失条码和邮箱、同名商品、内部 SKU 编码。
- 门店归属历史、会员等级历史、日末库存快照、活动商品桥表和营销触达均有数据。
- 每个退款包含两个退款明细，可稳定复现订单明细与退款明细直接 Join 的行数放大。

## 安全与版本

生成脚本只允许本机 `nova_retail`，要求 owner 身份、`--reset` 和 `--confirm-database nova_retail`。每次成功运行把 profile、seed、业务时钟、版本、各表行数、质量摘要和快照校验和写入 `atlas_internal.dataset_run`。

`datasets/fixtures/dirty_cases.yaml` 只定义失败测试，不会被正常生成器读取。这样可以验证外键、金额和状态错误，同时保持默认基准快照可信。
